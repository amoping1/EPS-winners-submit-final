Three systems, one entry

Three agents.
One vote.

We built three forecasting systems independently — same brief, same frozen corpus, same twelve targets, no shared code. The submitted figures are what those three systems agree on, with outliers voted out.

Architecture

Four evidence channels, three independent systems, one consensus. Everything sits behind a single point-in-time cutoff.

Three different approaches, in a sentence each

They were not divided up by company or by task. Each of us built a whole forecaster, and each answered the same question differently.

Neva Measure it

Builds a history for each metric out of earnings releases, forecasts the next period as the same quarter a year earlier moved by recent growth, and calls a model only on the six metrics that a 32-quarter historical replay measures the deterministic path as handling badly.

Adrian Anchor it

Gathers evidence per metric kept separate by channel — filings, history, market — anchors each figure to published guidance and sell-side analyst consensus but rejects any anchor whose reporting period does not match the one being forecast, then runs a critic pass over every metric before accepting it.

Dimitris Verify it

Splits the work across four agents that each own one source type — filings, financial statements, news, the company's own guidance track record — returning typed reports with citations, then has a coordinator re-evaluate the arithmetic the model claims: if the stated calculation does not reproduce the stated number, it sends back a repair request rather than accepting the figure.

These complement each other rather than overlap. Neva's tells you which metrics to trust, Adrian's ties every figure to something external, and Dimitris' checks that the stated calculation is real. Three systems that do not make the same mistake is the entire reason the vote works.

How the vote works

Three estimates are enough to reject an outlier and not enough to fit anything cleverer. So the rule is deliberately blunt.

Neva's system was outvoted most often, four times of twelve. Its ADI adjusted gross margin read 69.2 against 73.0 and 74.1 — the filing states 73.0. The ensemble removed a real error without being told which system was wrong, which is the whole argument for running three.

A caveat we would rather state than have found: a low backtest error proves the method is self-consistent, not that the right quantity was extracted. Forecast and actual are read by the same extractor, so a bias shared by both stays invisible. That is precisely the failure the three-system vote catches, because the other two systems do not share the bias.

Reproducing this

python run.py --as-of 2026-08-16          # this system's twelve figures
python scripts/collect_team_forecasts.py  # read all three systems' outputs
python scripts/build_ensemble.py --write  # vote, validate, write the workbooks
npm run check:submission                  # the organisers' validator

No credentials are required to reproduce the submitted figures: the market snapshot and every run artifact are committed, and the corpus ships with the repository.
